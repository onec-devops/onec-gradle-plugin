# Введение

Gradle-плагин для автоматизации разработки проектов на платформе 1С:Предприятие.

:::warning

Плагин в начальной стадии разработки, и стабильной версии у него пока нет. Новая версия может
содержать несовместимые изменения или устаревшие элементы DSL. Что поменять в сборке при
переходе на такую версию, описано на странице [Обновление плагина](./upgrading.mdx).

:::

## Возможности {/* #features */}

- [Любой формат и тип проекта](#formats). Плагин собирает конфигурации, расширения, внешние
  обработки и отчёты из XML-выгрузки и из проекта 1С:EDT и сам определяет, что перед ним.
- [Многопроектная сборка](#multi-project). Конфигурация, её расширения, обработки
  и отчёты могут храниться в одном репозитории и собираться как одно решение.
- [Кастомизация и расширяемость](#extensible). Можно изменить настройки плагина и добавить свои
  задачи, например проверку кода с BSL Language Server.
- [Интеграция в экосистему Gradle](#gradle). Проект на 1С совместим с плагинами сообщества
  Gradle, а также с IDE и CI, которые поддерживают Gradle.

### Любой формат и тип проекта {/* #formats */}

Плагин рассчитан на любые проекты на 1С, исходный код которых хранится в репозитории:
конфигурации, расширения, внешние обработки и отчёты, в XML-выгрузке платформы или в
[формате 1С:EDT](./getting-started/preparing-sources.mdx#sources-directory). Тип проекта и формат выбираете вы.

Обычно же для каждого сочетания нужна своя последовательность команд: конфигурация, расширение и
внешняя обработка загружаются и сохраняются по-разному, а проект 1С:EDT перед этим нужно ещё
выгрузить в XML. Когда проект переходит из конфигуратора в 1С:EDT, сборку приходится переписывать.

Плагин сам определяет формат и тип проекта по исходному коду и
[собирает](./reference/tasks.mdx#onecbuild) любой из них одной и той же командой. При переходе с XML на
1С:EDT в сборке меняется одна настройка - версия 1С:EDT.

### Многопроектная сборка {/* #multi-project */}

Плагин поддерживает [многопроектные сборки](./guides/multi-project-builds.mdx) Gradle: связанные
проекты хранятся в одном репозитории и собираются вместе. Например, конфигурация центрального
офиса и конфигурация для касс магазинов, которые обмениваются с ней данными.

Без плагина каждый файл собирается своим вызовом в скрипте: порядок вызовов и общие настройки
вроде версии платформы приходится повторять для каждого проекта, а каждый новый проект добавляет
ещё один вызов.

С плагином можно собрать сразу все проекты или только один из них. Новый проект
добавляется подкаталогом и одной строкой в настройках сборки. Проекты могут собираться параллельно
и не мешают друг другу, а общие настройки задаются один раз в
[плагине-соглашении](https://docs.gradle.org/current/userguide/implementing_gradle_plugins_convention.html).

### Кастомизация и расширяемость {/* #extensible */}

Плагин можно [настроить](./reference/extension.mdx) под проект, а в проект добавить свои задачи:
и шаги сборки, и отдельные действия. Например, проверять код с
[BSL Language Server](https://1c-syntax.github.io/bsl-language-server/) перед сборкой или
публиковать артефакты в Nexus.

Без плагина такие задачи хранятся в отдельных скриптах рядом со сборкой: у каждой свой запуск, а
общие правила для нескольких репозиториев копируются из одного в другой.

С плагином свои задачи можно написать на Kotlin или Groovy прямо в скрипте сборки, а общие
настройки и задачи задать в [плагине-соглашении](https://docs.gradle.org/current/userguide/implementing_gradle_plugins_convention.html),
которое подключается к проекту одной строкой.

### Интеграция в экосистему Gradle {/* #gradle */}

Плагин встраивает проект на 1С в экосистему Gradle. Инструменты, которые создавались для
проектов Gradle на Java или Kotlin, подходят и для проекта на 1С:
[поддержка Gradle в IDE](https://docs.gradle.org/current/userguide/gradle_ides.html),
[интеграции с CI-системами](https://docs.gradle.org/current/userguide/gradle_on_ci.html) и
[плагины сообщества](https://docs.gradle.org/current/userguide/plugins.html).

Опыт работы с Gradle тоже переносится. Разработчику, который знаком с Gradle по другим проектам,
не нужно осваивать отдельный инструмент сборки для 1С, а ответы на вопросы о сборке можно искать в
документации и сообществе Gradle.
